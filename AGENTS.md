Этот файл содержит руководства и решения для ИИ-агентов при работе с Fusion 360 API в данном репозитории.

## 1. Кодировка кириллицы в Fusion 360 API (Windows / MCP)

### Проблема:
При вызове Python-скриптов во Fusion 360 под Windows через MCP/подпроцессы исходные строки с кириллицей в коде (например, `"Толщина стенок"`) декодируются интерпретатором через системную кодовую страницу Windows (CP1251/ANSI), вызывая искажение символов (mojibake: `Ð¢Ð¾...`).

### Решение:
Всегда формируйте кириллические строки для имен параметров (`p.name`) и комментариев (`p.comment`) через **Unicode-последовательности (`\u04...`)** или декодирование байт `b'...'.decode('utf-8')`.

```python
# ПРАВИЛЬНО:
param.name = "\u0422\u041e\u041b\u0429\u0418\u041d\u0410_\u0421\u0422\u0415\u041d\u041a\u0418"  # ТОЛЩИНА_СТЕНКИ
param.comment = "\u0422\u043e\u043b\u0449\u0438\u043d\u0430 \u0441\u0442\u0435\u043d\u043e\u043a \u0434\u0435\u0442\u0430\u043b\u0438"  # Комментарий к параметру
```

Fusion 360 нативно поддерживает UTF-8, поэтому созданные таким образом параметры и комментарии отображаются в интерфейсе **Design -> Change Parameters** идеально чистым русским текстом.

## 2. Выполнение скриптов через `fusion_mcp_execute`

1. **Режим записи (`readOnly: false`)**:
   Для создания пользовательских параметров (`userParameters.add`) или изменения выражений (`param.expression = ...`) в объекте `object` обязателен флаг `readOnly: false`. При `readOnly: true` Fusion выбрасывает исключение `RuntimeError: 3 : Cannot modify the design from a read-only context`.

2. **Заполнение всех полей схемы**:
   Инструмент `fusion_mcp_execute` требует передачи базовых значений для всех строковых/булевых полей внутри `object` (`action: "preview"`, `operation: "open"`, `purchaseInterest: "extension"`), иначе валидатор схемы MCP возвращает ошибку `Value 'null' is not a valid enum value`.

3. **Обработка ошибок**:
   В функции `def run(_context: str):` не перехватывайте исключения `try...except`, так как стектрейс исключения необходим агенту для отладки и итераций.
